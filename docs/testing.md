# Tests and CI

The module retains `go 1.20` and has no third-party module dependencies. The
reporting toolchain is separately pinned in `.github/go-version` (Go 1.27.3).

## Local checks

```sh
go test -race -covermode=atomic -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
go vet ./...
git diff --check
```

Keep full-module statement coverage at 100%; do not exclude production files or
packages to meet the threshold. Coverage is not a claim of complete branch,
input or concurrency coverage. Benchmarks run without race/coverage instrumentation.

The XML extension optimization adds differential tests against the previous
implementation, including ASCII/Unicode names, malformed names and invalid UTF-8,
XML escaping, tabs, CR/LF, empty text and literal entity spellings. Fuzz-discovered
compatibility inputs are retained under `testdata/fuzz/`. Names outside the known
ASCII fast path continue through the old decoder, including its historical edge
behavior. The optimization does not introduce stricter XML validation.

```sh
go test -run '^$' -fuzz '^FuzzExtensionNameCompatibility$' -fuzztime=30s
go test -run '^$' -fuzz '^FuzzExtensionTextCompatibility$' -fuzztime=30s
```

Normal tests execute seed/corpus cases; the commands above explore more inputs.
Existing namespace, mixed-content, malformed-extension, failed-writer, source
immutability and all-format regression tests remain in place.

## Workflows

- `quality.yml`: race tests, 100% total/per-package coverage gates, Go Report Card,
  `go vet`, two short differential fuzzing runs, and artifact upload. It uses the same reporting action versions as
  [cascadia](https://github.com/soulteary/cascadia/blob/main/.github/workflows/quality.yml),
  pinned to their resolved commits. The grade report is diagnostic; only the test
  action has a numeric gate. An A+ report can still list complexity findings.
- `test.yml`: compatibility tests and vet, Go 1.20.x on Ubuntu 22.04 and Go 1.27.3
  on current Linux/macOS/Windows runners. The old toolchain runs on an older
  supported runner rather than assuming compatibility with every newer host OS.
- `security.yml`: pinned GoSec and govulncheck actions, using the reporting Go
  version rather than scanning with an obsolete standard library.
- `benchmark.yml`: manual dispatch, five samples, one Go scheduler thread, raw
  artifact output. See [performance.md](performance.md).

PR jobs have `contents: read`. A separate main-only publish job receives
`contents: write`, verifies the checked-out main SHA is the tested SHA, and commits
only the five stable badge/report files with `[skip ci]`. A concurrent main change
causes publication to be skipped or the normal non-force push to be rejected.
Raw test logs and coverage profiles stay in artifacts, not report commits. No
external coverage service token is required. Repository branch protection may
require allowing the reporting bot or publishing reports through a separate PR;
without that permission checks/artifacts still work, but the publish job fails.

The inherited Gorilla project-board workflow and the duplicated old lint/Codecov
reporting setup are removed. No organization project token is used by this fork.
The Go Report Card checks replace the old golangci-lint workflow; GoSec and
vulnerability checks remain independent.
